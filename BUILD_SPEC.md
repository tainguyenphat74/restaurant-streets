## Completed architecture and maintenance guide

- `src/state/economy.ts` is the pure source of all costs, income, milestones, register limits, offline integration, customer counts, and rankings. `store.ts` exposes Zustand actions, session revenue, selection and toasts. All interfaces consume the same state.
- `tick.ts` owns the 100 ms active clock, 10-second saves, visibility transitions and claim/import/reset checkpoints. `save.ts` validates and serializes version 1, preserves precise numeric values, and catches storage failures. Migration currently accepts version 1 only.
- `StreetScene.ts` owns map graphics, store-driven buildings, bounded camera, pointer gestures, walkers and pooled coin sprites. Shutdown removes subscriptions, input, tweens and resize/motion listeners. Async asset loading checks scene lifetime. Camera projection is published only when scroll, zoom or viewport changes, with Phaser's centered zoom transform applied. `StreetTab.tsx` renders every label, coin button and street sign in React. No Phaser text or UI buttons.
- `?qa=1` exposes `window.restaurantQA()` only while Street is mounted. It returns a cloned, read-only snapshot of game data and camera diagnostics; it has no write actions. Browser tests use Settings import for advanced fixtures. Never use imported progress as visual gameplay evidence.
- Tailwind 4 is integrated with `@tailwindcss/postcss` and `@import "tailwindcss"`; Vite processes the real utility CSS. React remains 18 and Phaser remains 3. Vitest 5 requires Node 22.12+ or supported newer LTS. `npm ci` reproduces the committed lockfile. `npm run format` formats source/config/docs with Prettier.

### Economy and visual tuning

Edit restaurant names, costs, base incomes, colors and dishes in `src/data/restaurants.ts`. Global upgrade prices/multipliers live in `src/data/upgrades.ts`; fictional competitors live in `src/data/competitors.ts`. Change formulas only in `economy.ts`, and update the economy tests with intentional balance changes. Editing display rounding must never alter affordability checks.

Plot world locations are in `src/game/iso.ts`. `StreetScene.recenter()` controls the responsive street composition; zoom is clamped to 0.5–2. Walkers grow from 10 to 20 with logarithmic total income. Coin sprites use a fixed 12-object pool. Reduced motion suppresses walking, bouncing and coin tweens. Colors and responsive panels live in `src/style.css`.

### Replacing procedural art with AI-created PNG assets

Generate one object per image using this prompt:

> isometric 2:1 view, single [object], cozy cartoon game asset, soft light from top-left, bright saturated colors, centered, plain white background, no ground, no shadow

Remove the white background with `rembg` (or equivalent), export a transparent PNG, keep the 2:1 perspective, and align the ground contact at bottom center. Put the image under `public/assets/`, then add its key to `public/assets/manifest.json`:

```json
{
  "building_tomato_basil": {
    "file": "buildings/tomato_basil.png",
    "anchorX": 0.5,
    "anchorY": 1,
    "scale": 1
  }
}
```

Building keys are `building_` plus the restaurant id. Supported decorative keys include `tree`, `lamp`, `bench`, `walker`, and `coin`; tile keys are `grass`, `road`, `sidewalk`, and `water`. Tune scale to match the procedural building footprint (roughly 200×230 pixels) and tiles (128×64). Missing files or invalid manifest entries use procedural textures under the same keys. Restaurant previews come from the actual loaded Phaser texture. No source edits are needed to swap supported assets. Keep art original and licensed for distribution.
